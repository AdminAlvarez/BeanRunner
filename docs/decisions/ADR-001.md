# ADR-001: Selección del Lenguaje de Programación Base

## Estado
Aceptado

## Contexto y Problema
El servicio JobRunner debe gestionar procesos, señales, flujos de entrada y salida, sockets TCP y persistencia en Linux. El lenguaje elegido debe permitir implementar esas capacidades de forma fiable, mantener el código y facilitar la incorporación de funciones avanzadas. El equipo decidió migrar el esqueleto inicial de C++ a Python antes de desarrollar los módulos principales.

## Alternativas Consideradas

### Alternativa A: C++17
* **Ventajas:** Buen rendimiento y control de bajo nivel, con abstracciones de programación orientada a objetos y acceso a APIs del sistema.
* **Desventajas:** Requiere compilación y más trabajo para implementar y evolucionar funciones de alto nivel; el equipo estima que las futuras extensiones serían difíciles de mantener en este lenguaje.

### Alternativa B: Python 3
* **Ventajas:** Desarrollo y mantenimiento más ágiles, biblioteca estándar para procesos (`subprocess`), señales (`signal`), sockets (`socket`) y JSON (`json`), y sin paso de compilación.
* **Desventajas:** Mayor consumo de recursos y rendimiento potencialmente inferior para trabajo intensivo de CPU; la ejecución de trabajos externos sigue necesitando límites, validación y aislamiento a nivel de proceso.

## Decisión Seleccionada
Se selecciona la **Alternativa B: Python 3.10 o posterior**. La biblioteca estándar cubre las interfaces del sistema que necesita el servicio, mientras que el lenguaje reduce la complejidad de las futuras funciones y elimina la compilación nativa del flujo de desarrollo. Se conserva Linux como plataforma objetivo para el comportamiento del servicio.

## Consecuencias y Riesgos
* **Positivas:** Menos fricción para incorporar y mantener funciones, ejecución directa del código fuente y acceso a procesos, señales, sockets y archivos mediante módulos estándar.
* **Negativas:** Mayor uso de memoria y menor rendimiento que una implementación nativa en tareas intensivas; Python no elimina la necesidad de limitar y supervisar los procesos externos.
* **Mitigación de Riesgo:** Mantener pruebas automatizadas, usar `subprocess` sin invocar shells innecesariamente y validar los límites de concurrencia y recursos cuando se implemente el motor de trabajos.

## Requisitos Afectados
* RNF-01: Ejecución en Linux declarada.
* RNF-02: Ejecución reproducible mediante clon limpio, sin compilación nativa.
* RNF-17: Organización en módulos con responsabilidades identificables.
* RNF-19: Calidad y validación automatizada del código Python.

## Evidencia y Prototipo
La migración sustituye el punto de entrada C++ por `src/main.py` y reemplaza la verificación basada en compilador con pruebas de `unittest` y un script de verificación Python.
